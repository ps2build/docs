64 /*
65 * A poor-man error facility.
66 *
67 * This code being written in vanilla C, doesn't have the luxury of a
68 * language-supported exception mechanism such as the one available in
69 * Java. Instead, we are stuck with using error codes that must be
70 * carefully managed and preserved. However, it is convenient for us to
71 * model our error mechanism on a Java-like exception mechanism.
72 * When we assign an error code we are thus `throwing' an error.
73 *
74 * The preservation of an error code is done by coding convention.
75 * Upon a function call if the error code is anything other than
76 * `FT_Err_Ok', which is guaranteed to be zero, we
77 * will return without altering that error. This will allow the
78 * error to propagate and be handled at the appropriate location in
79 * the code.
80 *
81 * This allows a style of code where the error code is initialized
82 * up front and a block of calls are made with the error code only
83 * being checked after the block. If a new error occurs, the original
84 * error will be preserved and a functional no-op should result in any
85 * subsequent function that has an initial error code not equal to
86 * `FT_Err_Ok'.
87 *
88 * Errors are encoded by calling the `FT_THROW' macro. For example,
89 *
90 * {
91 * FT_Error e;
92 *
93 *
94 * ...
95 * e = FT_THROW( Out_Of_Memory );
96 * }
97 *
98 */
