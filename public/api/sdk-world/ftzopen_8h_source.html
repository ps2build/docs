64 /*
65 * state of LZW decompressor
66 *
67 * small technical note
68 * --------------------
69 *
70 * We use a few tricks in this implementation that are explained here to
71 * ease debugging and maintenance.
72 *
73 * - First of all, the `prefix' and `suffix' arrays contain the suffix
74 * and prefix for codes over 256; this means that
75 *
76 * prefix_of(code) == state->prefix[code-256]
77 * suffix_of(code) == state->suffix[code-256]
78 *
79 * Each prefix is a 16-bit code, and each suffix an 8-bit byte.
80 *
81 * Both arrays are stored in a single memory block, pointed to by
82 * `state->prefix'. This means that the following equality is always
83 * true:
84 *
85 * state->suffix == (FT_Byte*)(state->prefix + state->prefix_size)
86 *
87 * Of course, state->prefix_size is the number of prefix/suffix slots
88 * in the arrays, corresponding to codes 256..255+prefix_size.
89 *
90 * - `free_ent' is the index of the next free entry in the `prefix'
91 * and `suffix' arrays. This means that the corresponding `next free
92 * code' is really `256+free_ent'.
93 *
94 * Moreover, `max_free' is the maximum value that `free_ent' can reach.
95 *
96 * `max_free' corresponds to `(1 << max_bits) - 256'. Note that this
97 * value is always <= 0xFF00, which means that both `free_ent' and
98 * `max_free' can be stored in an FT_UInt variable, even on 16-bit
99 * machines.
100 *
101 * If `free_ent == max_free', you cannot add new codes to the
102 * prefix/suffix table.
103 *
104 * - `num_bits' is the current number of code bits, starting at 9 and
105 * growing each time `free_ent' reaches the value of `free_bits'. The
106 * latter is computed as follows
107 *
108 * if num_bits < max_bits:
109 * free_bits = (1 << num_bits)-256
110 * else:
111 * free_bits = max_free + 1
112 *
113 * Since the value of `max_free + 1' can never be reached by
114 * `free_ent', `num_bits' cannot grow larger than `max_bits'.
115 */
116
