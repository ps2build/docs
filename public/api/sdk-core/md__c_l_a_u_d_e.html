sdk-core

The core tier of the ps2build-based PS2 SDK: permissively-licensed, build-critical EE/IOP modules only - world (sibling repo) is where copyleft-allowed, non-essential packages live instead.

Roadmap - wanted from legacy ps2sdk

Found by the 2026-09-09 SDK Parity Ledger audit (ps2sdk vs sdk-core/ sdk-world module-by-module diff). All four have real, complete source in ps2sdk and are wanted here, core tier - each is either a peripheral driver in the same family as already-ported pad/kbd/mouse, or a system-level piece already neighboring core fundamentals like loadcore/modload/sysmem in ps2sdk/iop/system:

  • iopreboot (ps2sdk/ee/iopreboot) - EE-side library pairing with ioprpgen to replace/reboot the IOP's own core module image at runtime via UDNL. Highest priority of the four: a well-known, commonly-linked piece of classic PS2SDK, not a niche one.
  • reboot (ps2sdk/iop/system/reboot) - IOP-side server for modload's reboot function, used together with iopreboot/UDNL to swap in a new IOPRP image.
  • remote (ps2sdk/ee/rpc/remote) - EE-side RPC client for the SCPH-10160 infrared remote-control receiver.
  • rmreset (ps2sdk/iop/system/rmreset) - IOP-side driver that resets the SCPH-10160 receiver into gamepad-emulation mode. Pairs with remote above.
  • sdhd (ps2sdk/iop/sound/sdhd) - sound-bank access for files stored on an HDD unit. Same shape as already-ported core/ahx (format-specific sound-data access library), placed core to match.
  • sdsq (ps2sdk/iop/sound/sdsq) - sequenced-music (.SQ file) access. Same reasoning as sdhd.

Deferred until after the current toolchain release

Debug/diagnostic tooling and filesystem-check utilities from the same audit - real, but not release-blocking, and explicitly scheduled for after the current release rather than now:

iop_sbusdbg, iopdebug, ioptrap, thmon, udptty, filexio-verbose (debug consoles / instrumentation - devs only, no shipped title links these), fsck, fssk, hdck, hdsk (PFS/HDD consistency-check CLIs, not linkable libraries), dummymod (a stub/ placeholder test module with no real functionality).

The full module-by-module breakdown from that audit - including what was scoped out entirely (arcade/TOOL-devkit hardware) versus superseded/renamed - lives in the session that produced it, not in this repo.

DVR-P (core/dvr, core/dvrmisc, alongside already-ported core/pvrdrv/core/dvrfile) is in scope, unlike arcade/TOOL-devkit - also used on PS1 hardware, not devkit-only.
