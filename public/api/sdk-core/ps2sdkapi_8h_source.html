115/* ip4_addr_t/ip_addr_t/socklen_t/struct in_addr are all real types
116 * this file needs but doesn't define itself - <sys/socket.h>, included
117 * above, is their real, canonical home (see its own comments for why -
118 * the short version: this package's own legacy <sys/socket.h> used to
119 * pull them in via a blanket #include <tcpip.h>, a whole parallel,
120 * pre-lwip-migration copy of lwip's own types that conflicts outright
121 * with ps2ip's real lwip headers; replaced with real, minimal,
122 * lwip-compatible definitions). By the time this file's own typedefs
123 * below run, <sys/socket.h> has already provided all of them.
124 *
125 * t_ip_info is different: unlike the above, <sys/socket.h> does NOT
126 * reliably provide it. Which real file that literal include name
127 * resolves to depends on the consuming package's own include_dirs
128 * order - ps2ips (this package's small RPC-client sibling) wants
129 * libcglue's own <sys/socket.h>, but ps2ip (the real lwip stack
130 * package) deliberately puts lwip's own POSIX-compat <sys/socket.h>
131 * (a one-line "#include <lwip/sockets.h>" wrapper) earlier in its own
132 * include_dirs instead, since ps2ip.h/ps2ipee.h/ps2ip_ps2sdk.c need
133 * the real lwip_accept/err_t/pbuf/netif/tcpip chain that only lwip's
134 * own sockets.h transitively provides - see core/ps2ip/ps2.yaml's own
135 * comment. lwip's real sockets.h obviously has no concept of
136 * t_ip_info (a ps2sdk-specific struct, not a POSIX/lwip one), so it
137 * can't be left to <sys/socket.h> to supply here - given its own,
138 * independent, real definition instead, shared with libcglue's
139 * <sys/socket.h> via the same T_IP_INFO_DEFINED guard so whichever of
140 * the two headers is reached first in a given TU wins. */
